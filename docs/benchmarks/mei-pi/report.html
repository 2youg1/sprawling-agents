Mei and Pi

Headless performance on Linux x86_64 with a 4-vCPU quota and a 16 GiB memory limit. Mei 0.18.3 release build and Pi 1.6.1 on Node.js 24.22.3 ran against the same scripted workload.

The fixture verified output and tool calls across 40 interleaved rounds. For the tool workload Mei reused its Python guest and Pi launched the same code through Bash. This round describes the measured host and configuration. Live model speed, TUI and long-running memory are outside this matrix.

At eight parallel file tasks, Mei completed at P95 in 75.65 ms and Pi in 1,403.07 ms. Median batch throughput was 117.55 and 6.33 tasks/s respectively.

At the final-response barrier for eight file tasks, median tree PSS was 51.70 MiB for Mei and 610.96 MiB for Pi. For eight parallel short answers, task wall CV was 57.9% for Mei and 17.8% for Pi. Both central latency and relative variation matter when choosing a concurrency level.

Method and provenance

Mei was built in release mode with the repository's locked Rust dependencies at tag v0.18.3-261127 and commit 5123332fca7aa8a64703c4339e2890a64470dfb3. Pi used @earendil-works/pi-coding-agent@1.6.1. The host was a shared Debian container with Linux 6.18.57, 5 visible logical CPUs, overlay storage and uninstrumented background load. The toolchain used Rust 1.100.0, Python 3.12.14, Node.js 24.22.3 and uv 0.13.9.

Each timed batch started fresh headless processes and used a fresh workspace per task. One warm-up sweep primed the OS file cache and Mei's doctor cache. The 40 retained sweeps shuffled workload cells with seed 271127 and alternated the first product by round and cell. Task deadlines were 20 seconds. Pi ran in offline print mode with Bash as its tool, discovery and automatic compaction disabled. Mei used its public -p entry point and --resume for history. Pi used --session for history and an in-memory session for the other workloads. A loopback Anthropic Messages fixture returned JSON to Mei and SSE to Pi.

The short answer uses one request. The three-tool task reads a 64 KiB file, writes an uppercase copy and checks its SHA-256. The 64 KiB input sends the same generated text as part of a new prompt. Resume loads 16 alternating user and assistant messages totaling 1 MiB, followed by a new user prompt. Both clients must carry every history message on the wire in order. Fixture preparation is outside the clock.

Wall time runs from just before process spawn until the launcher observes exit and closes both output streams. Launch latency ends when the fixture reads the first request body. Fixture preparation ends at the start of its response-body write. The gap from that write until the next request body is a tool round trip. The fixture checks the expected request count, tool results and final output.

Active memory uses separate batches. All sessions wait at the final-response barrier before the sampler sums Linux smaps_rollup PSS for the agent processes and their descendants. This phase includes Mei's Python guest. Pi has already completed its short-lived tool subprocesses.

Read and verify the CSV

One row records either a task attempt or a batch. A blank attempt identifies the batch row. The cohort records the round, workload slot and interleaved product order. Outcome flags are one for pass and zero for fail. A blank field means the metric does not apply. The same observations are used for all graphs.

  • Convert wall_ns to milliseconds by dividing by 1,000,000.
  • Read model_spans_ns as pipe-separated start:end offsets from task launch. The first start gives launch-to-request time. Subtract start from end for fixture preparation and subtract one end from the next start for the tool round trip. The first such gap is the first tool call.
  • Batch throughput is parallel × 1,000,000,000 / batch_wall_ns for a verified batch. Active PSS in MiB is active_pss_kib / 1024.
  • Group by agent, workload, parallelism and metric. Sort values and use one-based ranks ceil(0.50 × n) and ceil(0.95 × n). CV is sample standard deviation divided by mean.
  • The descriptive 95% intervals use 10,000 circular-block bootstrap draws with four consecutive whole rounds per block and seed 271127. Whole rounds preserve within-batch observations and both agents use the same draws.
