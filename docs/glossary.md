# Concepts and vocabulary

> **For anyone who has to say what this thing does** — someone deciding whether to use it, someone about to operate it, someone about to change it. It answers what the words mean and how the pieces explain each other.
>
> It does not tell you how to install anything ([`getting-started.md`](getting-started.md)), how to run work day to day ([`operating.md`](operating.md)), or why the code has the shape it has ([`../ARCHITECTURE.md`](../ARCHITECTURE.md)).
>
> **This file says which word to use. Which words to avoid has its own single authority** — `tools/xtask/lexicon.toml`, consumed directly by the `lexicon` gate in CI. Read that file to check whether a phrasing is retired; keeping the list in one place is what stops a second authority from forming.

## How the pieces explain each other

A **city** is one directory on one machine, and everything else is inside it. It has one Ledger, which is its complete history, and it never references another city. You can copy the directory to another machine and it is the same city; you can delete it and nothing outside it changes.

Inside a city are **buildings**, and inside a building are floors and rooms. That hierarchy is the directory tree — not a model of it, the tree itself. So an **address** like `lab/room1` names a place on disk, and naming that place settles three separate questions at once: which files an agent may write, which documents it starts with, and who it reports to. A design that separated those three would need rules to keep them agreeing; here they cannot disagree, because they are one fact.

Work happens as a **run**. A run has a start and an end, an address it works at, and a task. It is not a person: a **resident** is the standing identity that survives across runs, with a file of its own that says who it is; a run is the expensive thing that happens when that identity is put to work. Confusing the two is how a design ends up paying for a hundred idle personalities.

Built-in model calls and writing tools record their intent durably in the **Ledger** before their outside effect; read-only calls may run before their call record is durable, and external harness activity is recorded from reports afterwards. Each recorded event is an **EventRecord**. Every other view of the city is a **projection** of that stream: the pages in the browser, the cost report, the recycle bin. Projections are disposable by construction, and the test that keeps them honest is to delete one and rebuild it from the Ledger and require the same bytes.

That is also what makes the interface trustworthy in a specific, narrow way: it can be wrong about what it has not been told, and it cannot be wrong in a way the Ledger does not also record.

Two more relations are worth stating because they are easy to invert. A **Gate** decides one action inside the city, and it decides it: the verdict is `Allow`, `Deny` or `Ask`, and exactly one door, `attach`, can answer `Ask`, because what it would grant is the reading right over every login a person's own browser holds, which no rule of the city's can answer (`kernel/src/gate.rs`). What a person answers in the Approval Inbox is that question, and it is a different thing from a question a resident asked about the design, which no door can settle. And a **Discard** is a deletion that carries its own way back: the type has no constructor without one, so a deletion with no restoration is not something the code refuses, it is something the code cannot express.

> The tables below are the vocabulary itself. The order is reading order rather than alphabetical order, because alphabetical order helps nobody on a first pass.

## 1 Space and identity

| Name | What it is |
|---|---|
| **City** | One city on one machine: one Ledger, one complete history. Two cities never reference each other. |
| **Building** | A building within a city. The scope unit for configuration, Archive, and the rules in `RULES.toml`. |
| **Floor** / **Room** | Floors and rooms inside a building. The directory tree is the space. |
| **Session** | A stretch of a room. Dispatching to a building with a name opens the room; dispatching into the room again goes on with the session it is in. **`/new` starts a new stretch at the same address** — the model and the effort the last one froze are forgotten, so the room may choose them again, and a person can change their mind about the model without losing the room. What crosses the boundary is chosen: `/new` carries nothing, `/new --carry` carries the room's `Handoff.md`. |
| **Carry** | What a new session keeps from the one before it. Two answers, both named on the wire: `nothing` (the default, and what `/new` means) and `handoff` (the previous session's summary travels, the frozen shape still goes). |
| **Origin** | Where a session branched off: a run, and the line of it the branch inherits through. A branch is a new session that opens with another run's conversation, so it is `/new` with an origin rather than a second verb — and the line written down is the one the conversation was actually cut at, which is earlier than the one asked for when that line fell inside a wave of tool calls. |
| **Build Floor** / **Workshop** | A floor given to one piece of collaborative work, and the node graph that routes work across it. |
| **Utilities** | The shared services of a city, in the reserved subtree: nothing a resident writes to. |
| **Resident** | A standing identity with an `URBANITE.md` and a dossier, surviving across runs. |
| **Ephemeral** | A derived worker discarded after use, with no standing identity. |
| **Neighbourhood** | The addresses one run can reach, and who stands at each: this building's rooms in full, the city's other buildings by name only. An empty room is listed as a place, because hiding it would read as "this address does not exist". Never called a directory — that word already names a place on disk. |
| **Run** | One piece of work with a start and an end. **A resident is an identity; an active run is the cost** — the two numbers differ by two orders of magnitude. |
| **Fork** | Branching a conversation: a new session whose first run opens with the conversation another run had up to a line of it. The lineage is recorded (`run_forked`) by the run that inherits; the page's verb is `/fork`, which sends the same `open_session` as `/new` with an origin added. |
| **resume** | Reopening a city after the process died: the chain is verified, tool calls whose outcome was lost are closed as unknown, and what waits for a person is reported. |
| **Address** | A path newtype relative to the city root. It sets the write domain, the default context, and who the work reports to. |
| **reserved prefix** | A `.sprawling/` or `.git/` directory and its subtree, at any depth, always outside every write domain. What governs a scope sits in the first — the city, and each building — and what keeps a repository itself (hooks, config, refs, objects) sits in the second, so writing either is writing one's own governance or escalating. An agent cannot edit its own accounting, its own configuration, or its own building's rules. |
| **read bound** | What a run may read by a path it chose: all of its own building, every other building that is not confidential, and nothing of a confidential building from outside it. A building whose rules cannot be read is closed the same way, because those rules may say `confidential = true`. `kernel::address::may_read` decides it; `read` and `search` ask before they touch a disk, and a transcript is read through them. |
| **City Hall** | The building `hall`, raised with the city. It holds the city's plan and the two residents who serve every other building; it holds no project of its own. |
| **person** | The one who owns the city and answers what its residents cannot: the `Owner` of **Autonomy**, spelled `person` as the `who` of a Ledger record and on the wire. The interface, the prompts and templates, the shipped skills and the documents written for that reader show it as **User**, with a capital U so it is not read as the provider message role `user`; Chinese copy writes User as well. Identifiers, comments, specifications and Ledger tokens keep `person`. |
| **Mayor** | The resident `hall/mayor`: the city's planner, writing Markdown only. It turns an idea into `<city>/hall/Roadmap.md`, hands each building its part through `plan`, and raises a building through `city`. Its identity is `<city>/.sprawling/MAYOR.md`. |
| **clerk** | The resident `hall/clerk`: answers approvals when the person delegated them, in the same three parts a Gate uses, with its reason in the Ledger. Its identity is `<city>/.sprawling/CLERK.md`. |
| **governed document** | One of the three files that govern a city rather than belonging to a resident: `MAYOR.md`, `CLERK.md`, `PREFERENCES.md`, all in the city's reserved subtree and all written through one door. The Mayor cannot edit who the Mayor is, the clerk cannot edit what it answers by, and neither can edit how the person wants their city run. |
| **identity area** | The TOML block fenced by two `+++` lines at the top of `PREFERENCES.md` (`user_id`, `imported_from`) and `MAYOR.md` (`name`): what the city calls the person and the Mayor. Read in one place, `city::Naming`; a file without one is read as all body. A session freezes the names its first run read, so renaming takes effect at the next `/new`. The names are what a person is called, never who may act: the Mayor is `hall/mayor` whatever it is called. |
| **Vocation** | What the residents at an address are there to do: `Builds`, or `Plans`. It is read off the building, and it decides the tool set a run is given — a resident of City Hall gets no `exec`, no `delegate` and no `workshop`, and gets `city` instead. |

## 2 History and content

| Name | What it is |
|---|---|
| **Ledger** | The only city history. Built-in model calls and writing tools record intent before their outside effect; external harnesses contribute reports afterwards. |
| **EventRecord** | One line of the Ledger, carrying `seq`, `prev`, `t`, `kind`, and a payload. Payloads hold integers. |
| **EventDraft** | An event that has not yet been given a `seq` and a `prev`. Only the Ledger port turns one into an EventRecord. |
| **EventRef** | A reference to an event. **Privately minted**: no public constructor and no serde, so a forged reference cannot be spelled. |
| **Locator** | The retrieval grammar, `cas:` or `file:`. Fail-closed: a shape that does not match is refused rather than guessed. |
| **Citation** | A quote paired with the `cas:` or `file:` Locator range it claims to come from. A verification run compares it, after collapsing whitespace, against the version pinned for review; a citation that names another version does not hold even when the words match. |
| **CAS** | Content-addressed store (BLAKE3). Identical content is stored once for its lifetime. |
| **document version** | All the bytes of one file of the city at one moment, identified by their BLAKE3 digest, which is also the address the CAS gives those bytes. A page reads a version, and a save names the version it was made on, so a save made on a version that has since moved is refused rather than written over the change that moved it (`crates/documents/Spec.lean` D3, D8). |
| **document window** | The stretch of one document version one answer carries: never past the version's end, never more than `WINDOW_BYTES_MAX` bytes past the offset it was asked from, and never splitting a character. Windows read end to end are the version, byte for byte (`crates/documents/Spec.lean` D7). |
| **draft** | Text a person has typed into a document and not saved. It lives in the browser only; the city never holds one, so a draft survives a refused save and a lost connection on the page that holds it. |
| **proposal** | One suggestion a run makes about one document: a stretch of bytes of one document version and the text it suggests in their place, shown to a person as a card of review slices and decided sentence by sentence. Its identity is a digest of the run, the document, the version, the stretch and both texts, so it reads back the same from the Ledger. The person accepts, amends or rejects; the run may withdraw it while it is open; a card is handled once (`crates/documents/Spec.lean` D13–D19). |
| **review slice** | One sentence of a proposal card, with the whitespace around it, marked as kept on both sides, deleted, or inserted. The slices of either side read in order give back that side byte for byte, which is why accepting every slice gives the proposed text and rejecting every slice gives the original (`crates/documents/Spec.lean` D14). |
| **preview** | One window of a Markdown document version, laid out by the city's one Markdown grammar as blocks and inline marks: data a page draws as elements, never HTML. What the grammar reads but the page does not draw - HTML, a formula, front matter - comes back as `Unsupported` with its source text, so a construct left undrawn and an empty document are different answers (`crates/documents/Spec.lean` D21, D22, D25). A model's reply is laid out by the same grammar through `Query::Reply`: a settled reply exactly as the preview of a version holding its text, one still streaming up to its **closure point** (D30). |
| **closure point** | In a reply still streaming, the byte after which nothing already laid out can change: just past the last complete line that is blank outside a code block, is a heading at the margin, or closes a code block opened at the margin. It only moves forward; the text after it is drawn as it arrives (`crates/documents/Spec.lean` D31). |
| **projection** | A view rebuilt from the event stream. **Disposable**: deleting the table and rebuilding from the Ledger gives byte-identical results. |
| **playback bundle** | A stretch of one city's Ledger exported for review (`sprawling playback export`): the selected lines verbatim, the runs, key moments, messages, checkpoints and costs derived from the lines the reader may see, a count of what was withheld, and a `source` naming the city, the selection, the cutoff and the projection rules. Its bytes are canonical, so exporting the same history twice gives the same bytes, and `sprawling playback check --city` recomputes it rather than trusting it. It is a projection, never a second history (`crates/accounting/Spec.lean` §8-12). |
| **cutoff** | The last complete Ledger line an export verified, fixed when the export starts. Nothing a playback bundle says was read past it: a run's state, a key moment's closing, and the context of a selected line are all as of the cutoff. |
| **playback page** | A single self-contained HTML file that carries one playback bundle byte for byte in its `playback-bundle` script block, written by an agent with the `playback` skill. `sprawling playback check` reports it as five separate items — structure and references, the same as a given bundle, recomputed from its city, static offline, and browser observation — each passed, failed or unchecked, because a static pass and an observed browser are different claims (`crates/accounting/Spec.lean` §8-13). |
| **playback exports** | The place under a city's reserved subtree, `.sprawling/playback/<building>/`, where residents' playback bundles and pages land through the `playback` city tool: outside every write domain and every worktree, and out of git's history (kernel `CityLayout::playback_exports`, `crates/sprawling/Spec.lean` §8-132). |
| **Snapshot** | The same idea inside the browser (`client/src/core/belief.ts`): equally disposable, equally forward-only. |
| **verified prefix** | The first bytes of a Ledger segment, up to a length a record names, that a strict walk of the chain already checked; the record keeps their BLAKE3 digest, the rule version, and the chain state entering and leaving them. A later proof that finds the same digest, version and entry state takes the record's exit instead of checking those lines again (`crates/storage/Spec.lean` §8-30). A projection: deleting the records costs one strict walk. Not "sealed segment": a segment whose successor was lost in a crash grows again, and a record covers a prefix, not a segment. |
| **Provenance** | The five facts a commit the city makes carries as git trailers — `Sprawling-Run`, `Sprawling-Actor`, `Sprawling-Model`, `Sprawling-Effort`, `Sprawling-City` — and a sixth, `Sprawling-Predecessor`, when the run replaced another. A projection of the Ledger for readers outside the city; the Ledger stays the authority and the commit id reconciles the two. |
| **patch** | The text of one file's change between two checkpoints, asked for one file at a time. It is a separate request from the list of what moved, because patch text is file content on a socket: every line a credential scan matches is withheld and named by its line number, never echoed. |
| **checkpoint** | A commit the city makes so a change can be shown and reverted: a base checkpoint when a building's folder is adopted or first worked in, and one before and after each tool wave. A wave checkpoint lives under `refs/sprawling/runs/`; a base checkpoint moves the person's branch only in a repository that had no commit yet. Each one is recorded as `checkpoint_committed`. It is not a Ledger snapshot. |
| **landing commit** | The one commit a reviewing run makes on its worktree branch when it offers a pull request; the merge that follows is the only commit trunk receives. |
| **accounting thread** | The city's one writer. It alone holds the Ledger, the endpoint book, the plans, the pursuits, the governance fold and the desks, and it alone settles what a run left behind — in the order the results arrive. |
| **driving pool** | The threads that drive runs. One of them is a **lane**, and it lives exactly as long as the run it drives: it holds that run's driving state and nothing else — no Ledger, no book, no desk. The pool sets no lane count: a prepared run gets a lane at once and the pool asks only for memory, so the one concurrency limit is each endpoint's **provider queue** (`crates/sprawling/Spec.lean` D34). citysim drives no lanes at all, because a scenario is a fixed script replayed on one thread. |
| **seat** | The logical processor the placement table gives a hot thread of the city as it starts: the least-occupied core, the better one on a tie, kept until the thread exits (`crates/sprawling/spec/Serving/Placement.lean`). The hot threads are the accounting thread, the view fold and the socket workers. On Windows the seat is the thread's ideal processor, a preference the system may override when that core is busy; macOS and Linux make no placement call. |
| **relay** | The Ledger adapter a driving thread writes through. It carries the EventDraft to the accounting thread and waits for the answer, so `Ok` still means durable and the city still has one writer. |

## 3 Context and turns

| Name | What it is |
|---|---|
| **frozen prefix** | The frozen prefix in four segments — city, Building, Resident, Run. Assembling it is itself an event. |
| **Handoff** | The five-section artifact that carries a session across a freeze or a resume. |
| **turn** | The turn state machine: four phases, four cancellation-safe points. An interruption inside a phase cannot be spelled. |
| **held lines** | The Ledger lines a run has written but not yet made durable (`runtime::turn::ledger::HeldLines`). They belong to the run, not to one turn, so a turn's tool wave rides the next durability barrier: the one after the next `model_called`, before the next write, or before the run freezes, is cancelled or writes a carrier event. A turn pays one barrier plus one per write. |
| **first content** | The first non-empty prose or reasoning a streamed reply delivers. The turn reads its clock when it arrives and records the moment as `first_at` on `model_returned`; the time to first content is that moment minus the `model_called` line's `t`. A reply that came through a door with no stream, or streamed only tool calls, has none. |
| **Steer** | A redirection: add an instruction to a run **without interrupting it**. It lands at the end of the next tool result. |
| **Cancel** | Stop this run. When Cancel and Steer meet on the same boundary, Cancel wins. |
| **result envelope** | The envelope around a tool result, carrying three attachments: clock stamp, network reminder, and Steer. |
| **ClockStamp** | The clock stamp. With the feature off, output is byte-identical to a build that never had it. |
| **ceiling ladder** | The ordered statements about how many tokens one model may write, read farthest-to-nearest until one answers: the figure the person entered, then the provider's own model list, then a preset row citing the page it was read from, then the city's policy default. Which rung answered travels with the decision as `ceiling_from` in `model_selected`, so a truncated answer is read off the account rather than guessed at. A model no statement covers is still callable, which is what the ladder exists to guarantee — the Anthropic wire refuses a request that names no ceiling. |
| **context reminder** | The line that says how full the window is, computed from the provider's reported `input_tokens` against the model's `context_tokens` and never from a byte count. Two thresholds: 30%, and a second one the person may move between 31% and 90% (65% unless a layer states one), so the two never coincide; each sounds once per run, and the second says the budget left is still enough to write a handoff and `succeed`. |

## 4 Decisions and safety

| Name | What it is |
|---|---|
| **Gate** | The doors, listed as data in `kernel::gate::DOORS` so that a door added to the enum is a door the refusal matrix judges. Each door returns an exhaustive verdict rather than a bool; an outward action also carries a deduplication key (`kernel::idem`) that resume and replay derive again identically, so a recovered run does not send it twice. |
| **three-part refusal** | A refusal states what was refused, why, and an alternative that can be acted on. |
| **Taint** | External content is data. Taint joins on the union, has no unwrapping surface, and refuses two doors outright: an undoable effect and a discard are both denied once tainted text has reached the run that asked for them. |
| **WriteDomain** | The set of prefixes a resident may write, and what it may write inside them: `Everything`, or `Documents` — Markdown files only, and never a plan file. The decision primitive is `Address::is_within`; a building declares the second half with one `write` key in its `RULES.toml`. |
| **Documents** | The narrower of the two write-domain kinds: inside its prefixes a resident may write Markdown files and nothing else, and never a plan file. A building declares it with one `write` key in its `RULES.toml`; the wider kind is `Everything`. It is what a resident who plans is given, so a planner cannot reach into what a builder produces. |
| **run policy** | The four values one run works under, chosen when it is dispatched and written into its `run_started` line: its **mode**, its **write limit**, its **admission requirement** and its **landing policy** (`kernel::RunPolicy`). They are chosen independently, so a create-only experiment and a chat that must show its tests are both one value. |
| **mode** | Whether a run is talking with the person (`chat`) or carrying out work (`work`). It decides how the run's catalog row introduces it and nothing else; what it may write, what it must prove and whether it lands are the other three values of the run policy. A plan is not a mode: it enters through the fixed SDD workflow of `/plan`. |
| **write limit** | What a run may do to a file that already exists inside its write domain: `full` adds no narrowing, and **`Create`** — "read-only, may create" on the page — lets it create a file that does not exist and change, remove or rename none, including one it created itself. It narrows the building's WriteDomain and never widens it. A create is atomic: of two racing creates of one name, one succeeds. |
| **admission requirement** | The evidence a run's work must carry before a merge lets it into the building: `standing` (what the building's own rules already demand, nothing more), `tested`, `contract_kept` or `double_validated`. Choosing one does not provide the evidence, and none of them lifts a check the building already makes. Not to be confused with `Evidence`, the ledger lines a finished run cites. |
| **landing policy** | Whether a run's work takes the ordinary road (`ordinary`) or stays in an **experiment**: a worktree of its own, even in a building without review, from which nothing is ever merged. An experiment combines with any write limit. |
| **undoable effect** | An effect outside this city that nothing inside it can take back, such as a key pressed or a clipboard replaced through the **desktop connector**. It has no Restoration, so the Discard door has nothing to check; the door for it decides from what the connector was allowed at attach, because refusing every one of them would make the tool equivalent to absent. One allowance per connector, not per tool. |
| **Sealed\<T\>** | A sealed value: no Debug, no Display, no Serialize, no Clone. |
| **SecretRef** | `secret:<realm>/<name>`. Configuration holds the reference; the Vault resolves the value at authorized authentication sinks. |
| **Custody** | Credential custody: capture, replace in place with a reference, redeem at the wire. |
| **Discard** | Deletion. A Discard without a Restoration cannot be constructed. |
| **Restoration** | The way back: `Tracked` (committed), `Interred` (in the store), `Rebuildable` (reproducible). |
| **Recycle Bin** | The view over discarded things, where every row can state its own way back. |
| **ApprovalItem** | A design question a resident asked the person, awaiting an answer, carrying a cluster key and a tainted flag. Actions are not asked about here: a door allows one or refuses it, and the one door that asks, `attach`, asks through its refusal. |
| **Reading Room** | The list of skills a building admits. A name on it that is not on the shelves is left out rather than promised. |
| **Autonomy** | Who answers a question: `Owner` — the person — or `Delegate`, a resident who answers in their place. |
| **Halt** | The brake, and the only one: stop a city, a building, or a workshop; `release` lets it go on. It shuts the scope to new work and terminates the backlog members inside it, so a command nobody can reach is not what a stopped city is still doing. Ending a run that is already going is `Cancel`, which is a different verb. There is no spend ceiling and no turn ceiling behind it — a city that must stop is stopped by somebody saying so. |

## 5 Tools and the outside

| Name | What it is |
|---|---|
| **exec** | The tool that runs a program, a Python artifact, or a shell line, inside the sandbox the frozen configuration allows. |
| **environment passthrough** | The environment variable names a building declares its `exec` children may inherit, in its `CONFIG.toml` `[sandbox]` section, on top of the four every run gets. A name shaped like a credential is refused where the file is read. It is a declaration rather than a longer built-in list because what a child inherits, it cannot forget. |
| **edit** | The tool that changes a file, against a base version, inside the write domain. |
| **status** | The tool that answers what a run's own situation is: its run policy, context used against the window it was given, what waits for it, and how many neighbours it has. It states no spend ceiling, because there is none. |
| **neighbours** | The tool that lists the Neighbourhood: this building's addresses with the line each resident's `URBANITE.md` offers about what to bring them, or the city's buildings by name. An address it does not list has no reader. |
| **read** | The tool that opens one file by its path, or one catalog entry — a skill, a mode, the developer entry — by the name the catalog lists it under. A model-chosen path never reaches a reserved subtree; a catalog name may, because a person admitted it. It answers by line interval: at most 512 lines, and a truncated answer states the total and the offset to continue from. |
| **search** | The tool that finds a substring under one address prefix, with the lines around each hit and the line number `read` continues from. A substring, never a regular expression, so a pattern a model wrote wrong cannot become a stall; the same predicate `read` uses keeps it out of a reserved subtree. |
| **truncation lock** | What a capability a session does not use costs it, in three tiers per building and per session (a delegated run is a session of its own): not admitted to the building, zero bytes anywhere; admitted and not in the mode's core, one line in the dormant index; needed, its whole guide fetched with `describe` and the tool called through `call`. The request's tool list never changes inside a session, so a fetched guide arrives as a tool result and the prompt cache survives it (`runtime::catalog`). |
| **dormant index** | The one block of the frozen prefix that names the capabilities a building admits and a session does not carry as tools: one line each, a hint cut to its first sentence, names alone past the budget, then `+N more`. The whole block is at most 1 KiB. |
| **describe** | The tool that answers what an admitted capability is: given its whole name, the full guide (a tool's description and input schema, a skill's line and the name `read` opens it by); given a few words, the closest names by a fixed keyword ranking. |
| **call** | The tool that runs a dormant tool by name: the city checks the arguments against that tool's schema and refuses with the schema when they do not fit, and the call then passes the same doors as one made directly. |
| **official harness** | One of the five vendor harnesses the person approved — Claude Code, Codex, Grok Build, Kimi Code, Pi — which this city starts as an ACP agent. A subscription reaches the city this way: the person signs in inside the harness, and the city records what the harness reports without governing its tools. |
| **known host** | A vendor host the city's preset table lists, with the faces its documentation says it answers on and the base URL each face is called at. The settings page offers them, so a person picks a vendor instead of pasting an address. |
| **connection kind** | How one registered endpoint is talked to, settled once when it is attached and never derived again: an OpenAI-compatible chat face, the responses face, or the Anthropic native face. It is written into `endpoint_attached` and read back by `Query::Config`, so no call path re-derives it. |
| **dialect** (兼容格式) | The request and reply format one provider speaks — OpenAI-shaped or Anthropic-shaped. `gateway::dialect` translates between the canonical shape and one of them, in both directions. Chinese prose says 兼容格式; the identifier stays English. |
| **Endpoint** | One provider's chat URL, dialect, credential and headers. The city reaches an **external provider** only through one. |
| **route** | What makes the remote listener on the city's loopback reachable from outside, and nothing more: a Cloudflare named tunnel by default, or a command the person wrote (`remote_access::route`). It carries bytes. The handshake authenticates keys pinned at pairing and every frame is sealed, so a route that sees or changes frames learns nothing; the one trust it keeps is that it delivers the page unchanged. The local network face a `serve` bound with a pairing token is not a route. |
| **console confirmation** | The second step that opening the remote door or replacing the city key takes when the page asks for it (`remote_access::confirm`). The request prints a code on the city's console beside the verb it would perform; the verb is performed only when the next answer carries that code before it expires, two minutes later. The code never reaches a page or a frame, so a tool that drives the page cannot finish the step. A city without a console refuses the request. |
| **permanence** | Whether a route's host name survives the route being restarted: `Fixed` or `PerStart`. A device keeps its key and its installed page per host name, so a route whose host changes on each start leaves every paired device pairing again. |
| **Connector** | An external tool server a building configured, reached over MCP. Its tools carry a `Connector` effect, so the egress door knows where they go without a model naming a host. |
| **transcription** | The line of text a **recording** of speech became, produced by an optional endpoint speaking the OpenAI audio wire. Never called a transcript — that word already names what one run saw. Optional means the city works without one attached and says so in a refusal a person can act on, rather than answering nothing. |
| **Image** | A content block a model can see: a locator into the CAS, a media type, and integer dimensions. Bytes reach the wire only when the request is sent, never the Ledger. |
| **browser** | The tool that drives a browser over WebDriver BiDi: open, snapshot, act, screenshot, measure, console, viewport, close. A building gets it by writing `browser = true`; the city starts the engine itself (`bin::browser_bidi`) with that building's own profile, prefers Firefox because Firefox speaks the protocol without a driver, and downloads nothing. |
| **desktop connector** | The MCP server this binary runs as `sprawling desktop`, started by the city for a building whose `RULES.toml` says `desktop = true`; its code is the `crates/desktop` package: windows, snapshot, act, screenshot, record, clipboard, in the browser tool's vocabulary, inside an allowlist the building wrote in `DESKTOP.toml`. Two doors stand in front of it, in this order: `desktop = true` in the building's `RULES.toml` decides whether it may be attached at all, and the allowlist decides which windows on this machine it may then touch. |
| **doctor** | `sprawling doctor`: what this machine has against what a city needs, in two tiers — enough to use, enough to develop — and, with `--install`, one consented installation at a time. It is the one authority on what this machine has: the exec tool and the browser engine ask it rather than the machine. With a city named it judges each building's capability bits (`browser`, `desktop`, `sandbox.shell`) against this machine; with `--explain <code>` it connects a refusal code to the items behind it. What it installs lands in `~/.sprawling/components/`, at machine level and never inside a city. |
| **privacy control** | One setting on the host that this binary may change for the person on request: a registry value, a user environment variable or a scheduled task, with the snapshot it recommends, its scope (user, or machine through a UAC prompt) and the page category it shows under. The controls are defined once, in `bin::privacy::controls`; the page and the wire carry only their names. A control is applied or restored one at a time, each after a confirmation that binds the value the page showed, and every write is read back before it counts. Not a catalog entry: catalog names the tool and skill listing a run sees. |
| **original item** | One line of the privacy request list as the person wrote it, numbered K01 to K52. Each one either writes a privacy control, shared with any other line that names the same target, or is not written, with a reason from a closed set: the target is absent, obsolete or undeterminable. |
| **operation kind** | How a privacy control is written, from a closed set of four: a machine registry value, a user registry value, a user environment variable, or a scheduled task's enabled state. Real writes of each kind are tested only on a disposable Windows runner; no test writes the person's own machine. |
| **gauge** | `sprawling gauge`: measures a command over n runs, a running process and its descendants, or a served city's monitor, and writes each reading to stdout — one JSON line per reading to a pipe or a file, lines in units at a terminal. Readings are this machine's facts at one moment and never enter the Ledger. `top` is another name for the same verb. Not **measure**, which is the browser's action that reads an element's box. |
| **sieve** | The pass that decides what survives a command's output, by which command produced it. Deterministic and compulsory; so is the tee behind it, so nothing it cuts is unreachable. Distinct from **compaction**, which reads the shape of a text rather than the identity of its author. |
| **backlog** | The table of work that is running while the run goes on: background commands and delegated runs. Halt reaches into it; `status` reports the part of it that belongs to this run. |
| **succession** | A run replacing itself: same address, same depth, therefore the same tools — a successor is not a delegate, which is why it may delegate. It carries a handoff and the address of the conversation that produced it, and it needs no person. |
| **lineage** | The chain of runs a succession leaves behind. `Provenance` names each one's predecessor, so "how many times has this resident replaced itself since I last looked" is one question with one answer. |
| **transcript** | What one run actually saw, written beside its room as `<run-id>.jsonl` when the run freezes: the messages, the calls, the results as the model received them. Not the Ledger — the Ledger is the city's, this is the run's, and only the second one is a thing a resident may read. |
| **conversation** | The volatile half of a request: the messages a run's executor carries and folds forward turn by turn, handed to the model beneath the frozen prefix on every call, and gone when the process stops (`runtime::conversation::Conversation`). Not the **transcript** — that is the frozen per-run file written once the run ends — and not the context window, which is `kernel::Window`, the number of tokens a model accepts. A fork rebuilds a conversation from the Ledger rather than copying it. |
| **sandbox arm** | One way `exec` can be confined, chosen by a name that every platform can fill: `none` (the host itself), `copied_tree`, `native` (the platform's own mechanism: a Job Object with AppContainer on Windows, a Seatbelt profile on macOS, the `bwrap` namespace wrapper on Linux), `container` (Docker or Podman, installed apart), and `python` (Python inside wasip1). Each arm states which of the five guarantees — files, network, process tree, user, resources — it keeps. Selection and its platform conditions are described under [execution boundaries](operating.md#how-exec-is-confined); the run's disclosure states its actual route, and an arm the User names explicitly refuses when unavailable. |
| **skill audit** | The check a skill gets after it lands on a shelf, and again when a scan finds content no audit covers, recorded as `skill_audited` lines that bind each verdict to the digest of the whole content it judged. A skill shows as audited only while its content still has that digest, so changed content reads as stale until it is audited again (city D19). The source is the skills.sh partner audit by default, or SkillSpector when it is installed; an audit that could not be reached is recorded as such and never stops the shelving, and a skill no auditor applies to gets no line and shows as unaudited. The verdict is shown, not enforced: the Reading Room decides what a building admits. |
| **usage record** | The per-skill and per-MCP-tool table folded from the Ledger: a skill use is a `describe` or `read` of a skill the run pinned at `run_started`, an MCP use is a call of a tool an MCP server registered; each use carries its run, resident, time, the part read, and the outcome, with a count per UTC day and a row for every shelved skill never used. Content versions come from `skill_shelved`. It can be exported as JSONL or CSV (wire D33). |
| **held** | A signal a run took at a safe point and no recorded model answer has read yet. Its `signal_consumed` line is written when the run's next model answer lands; a run that leaves first gives it back to the room's queue, and the room is knocked once (collab D8). |
| **reply wait** | The synchronous half of `signal send`, asked for with `wait: true`: the sending run stops at a safe point, calls no model and spends no tokens, until the reply arrives, the run leaves its room, or `patience` (shorter than the provider's prompt-cache lifetime) runs out. The Ledger shows it as a `signal_wait_started` line paired with one `signal_wait_ended` (kernel D32), and a run in one carries `waiting` on the wire (wire D34). A run has at most one open reply wait, and a reply that lands before the run stops is kept for it (collab D15). The asynchronous half, the default, returns as soon as the signal is recorded. |
| **letter** | A resident's words as they reach another run's window: one `<letter from="@<room>" run="<run>" kind="steer\|reply" sender="<state>">` element inside a User-role message, with `<`, `>` and `&` in the body and the attributes escaped, so the body cannot close its letter or open a second one (collab D16, `crates/runtime/spec/Conversation.lean`). Not the **result envelope**, which wraps a tool result. A letter carries the standing of the resident that sent it and never the User's, even when it quotes the User. |
| **speaker** | Who said a line that reaches a run's window, as a type rather than a text prefix (`runtime::conversation::Speaker`): the User, whose steer is the only line that begins `user:` and is built only at the control surface; the city, whose own words (a policy change, a reply wait that ran out) begin `city:`; or a resident, whose words arrive as a **letter**. The wire's `Speaker` names the same three for the page. |
| **delivery outcome** | Where one sent signal landed, decided by the city just after its `signal_enqueued` line and recorded as the `signal_landed` line that follows it: `delivered` to a run working in the room, `queued` with nobody working there and no new run started, or `knocked` for a new run. Every sent signal has exactly one (kernel D38, `crates/collab/spec/Delivery.lean`); the send's tool line shows it. |
| **dispatcher** | Who handed a run its work: the User, the city, or a resident's run, recorded as `run_started.dispatched_by`. A delegated child's JOB.md names it in its `<from>` element and its opening line says the task was handed down by it, so a task a resident delegated never reads as one the User dispatched (city D21). |
| **handback** | What a delegated child reports to the room that delegated it when it ends: finished, with who verified it, or stopped, with the reason. It travels as a signal the city writes, and the parent's thread draws it with a link to the child's session. |
| **provider queue** | The calls waiting at one endpoint for a permit under its `max_in_flight`, served in arrival order and shed after `QUEUE_WAIT_MAX`; the only place a run waits for a provider. Its count and wait times are read per endpoint (gateway D20, D21). |

## 6 Interface

| Name | What it is |
|---|---|
| **wire** | The Commands, Queries and Events that pass between a city and its clients, owned by the `sprawling-wire` crate (lib `wire`); `WIRE_V` versions it. How a provider's API spells a request is that provider's dialect, not the wire. |
| **WebUI** | One page in a desktop browser, embedded in the binary and served from inside it. The one this tree carries is `client/`, TypeScript built by bun; the wire is the whole API, so how many clients exist is a fact about this tree rather than a limit of the design. |
| **world layer** | The bottom of the page's three layers: the city's sessions, commits and files, drawn beside the conversation or in its place and never under its words, because text over text is the slowest thing on a screen to read. How much of it is drawn is the **tier**'s decision. |
| **conversation layer** | The middle layer: the thread, its message heads and tool rows. |
| **edge layer** | What floats over the other two: the **edge keys**, the **mailbox**, the settings panel and the composer. |
| **tier** | How much of the **world layer** the page draws, one of three: `zen` draws none of it, `blend` draws whole panels beside the conversation, dimmed and not taking the pointer, and `panorama` makes it the workspace with the conversation as a band along the bottom. A preference of the person (`client/src/core/prefs.ts`). It is not a layer: the layers are what is stacked, the tier is how much of the bottom one shows. |
| **edge keys** | The three keys at the foot of the page's first column — layers, which cycles the **tier**; the **mailbox**; settings — and the only standing buttons the page has besides the composer's. |
| **mailbox** | The panel the second edge key opens: what waits for the person, the runs going, the recent sessions, and the notices. The **Approval Inbox** is one of its parts, not another name for it. |
| **settings tree** | The navigation of the settings panel, at most three levels deep, through which every page other than the conversation is reached. |
| **coin key** | The composer's one action key, with sending on one face and stopping on the other; which face is up depends on whether a run is in front of the person and whether the box holds words. |
| **context ring** | The one-pixel ring round the **coin key** that shows how much of the session's context window is used, with the two **context reminder** thresholds marked on it. |
| **inspector** | The right-hand pane where one tool call opens in full: its diff, its terminal output, the file it read. |
| **decide card** | The one shape of a thing that waits for the person's answer: a two-pixel leading bar and a glyph, a head saying who asks and when, a body that changes with the kind (a resident's design question, a gate waiting for the person, a proposal on a document), and at most three answers, each on one key — y yes, e yes as edited, n no (`client/src/views/parts/decide.svelte`). The same part stands in the conversation, in the **mailbox** and beside a document. |
| **read-wear scrollbar** | The pointer's scrollbar beside the thread: its track marks where each block sits, coloured by the run's phase, and darkens the stretches the viewport has already shown, so a person sees what they have read and where the waiting parts are (`client/src/views/talk/wear.svelte`). Wheel, touch and keyboard scrolling stay with the conversation column itself, so it is hidden from a screen reader. |
| **hold to reveal** | Holding the accelerator alone for 300 ms draws the name and key of each control on screen; letting go hides them. |
| **part** | One control in `client/src/views/parts/`, and the only implementation of it the client has: the button, the labelled field, the table, the tooltip. A screen composes parts rather than writing a control of its own, because a second implementation is where two behaviours begin to differ. |
| **interaction contract** | What a part owes a person who is not holding a pointer: the WAI-ARIA pattern it implements, what each key does, the exact `aria-*` values, and which element the focus returns to when the part closes. `client/Spec.lean` §9 is its single authority — how a screen is drawn is exempt from SPEC-first, and this is the half that is not. |
| **Lens** | Which reading of one history the record page is showing: `ledger`, `archive`, `bin`, or `log`, the process log (`client/src/core/route.ts`). Separate nav entries would ask a person to choose before the question was formed. The lens lives in the address, so a link to the archive is still a link to the archive. |
| **view** | The read-only verb `sprawling view <city>` that reads one city's Ledger from disk. It has two lenses: `tree`, the runs arranged by lineage (city, building, room, session, run), and `records`, the Ledger lines in seq order. When stdout is not a terminal it writes Ledger lines byte for byte, or one JSON line per run with `--runs`; at a terminal each Ledger line it shows is led by the line's chain hash, the value the next line holds as `prev`. It never changes the city. |
| **NewestRelease** | The query that asks which release this city is and which one npm offers, spelled `newest_release` on the wire. It is asked only when a person presses the button, and it is the only query that reaches the internet. It is not `release`, which is the verb that lets a halted scope go on. |
| **maturity** | How far the project stands, as every release it cuts names it: a value of `kernel::Maturity`. `kernel::release::MATURITY` is the one place it is written; the tag infix, the first line of `sprawling status` and the documents' `maturity` spans are rendered from it. |
| **display name** | What the User calls one session, recorded as a `session_named` line; the room's address stays its identity in the Ledger and in every read and write domain, and a session with no display name shows its address (kernel D22). |
| **session tag** | A label the User puts on a session, kept in the User's preference file and not in the Ledger; a session can carry several, and one with none shows a default tag taken from its workspace (`crates/wire/spec/Preference.lean` D21). |
| **control surface** | The verbs that intervene in work already running: `Steer`, `Cancel`, `Halt`, and `Release`, the way back out of a halt (`wire::control::Intervention`). |
| **Approval Inbox** | The queue of pending answers, grouped by cluster key. |
| **progress bar** | The part that shows how far along something is, as a bar and the two numbers it was drawn from; when the end is not known it says it is busy instead of claiming a fraction (`client/src/views/parts/progress.svelte`). |
| **ACCENT** | Acid blue, `H=250`, meaning "something is moving here, or this is the one chosen". |
| **ALERT** | Warm amber, `H=70`, ACCENT's complement, meaning "a person is needed here, or something is missing". |
| **single-hue language** | Every colour on one hue axis, ACCENT's, with ALERT as the one derived exception and the greys taken on the same axis; the two checkpoints of the **context ring**, green and red, are the only other hues, each named; `client/src/theme.css` holds the values. |

## 7 Construction vocabulary (not product concepts)

| Name | What it is |
|---|---|
| **SPEC** | A crate's construction authority, written before its code: `crates/<dir>/Spec.lean` with its parts under `spec/`, or `crates/<dir>/<lib>-SPEC.md` for a crate that has not migrated. It ships with the crate it governs, so a reader of the code has the reasons for it. |
| **shape** | Which of the seven module shapes a file instantiates — decision, value, port, adapter, typestate, data, projection. A module that cannot name its shape usually holds two things. |
| **seam** | A trait declared in the inner layer and implemented in the outer one. One adapter is a supposed seam; two make it real. |
| **conformance** | A generic assertion suite run against any implementation of a port. |
| **ablation** | Removing one passage of a document a model reads, and measuring what a resident stops being able to do without it. Run on demand for evidence about the document's length; never a gate. |
| **managed span** | A number in a document that a gate owns, wrapped in a pair of HTML comments that name the fact — the opening one spells `xtask:begin` and the fact's key, the closing one spells `xtask:end`. `cargo xtask docnum` recounts every such fact from the code that decides it and refuses a span whose text disagrees; `--write` corrects it. It is how a document quotes a figure without becoming a second home for it, because a figure typed by hand stays put while the code that decides it moves. |
| **not-proved marker** | The line `// not-proved: <reason>` above a kani harness that is written but is not proved today, stating the reason where the next reader is already standing. `cargo xtask proof` reads it to skip that harness and print why, so the source is the only roster and no second list can go stale. Deleting the line is how a harness comes back. |
| **gate** (lower case) | A machine guard in CI, run by `cargo xtask gates`. **Deliberately a homonym of the product's Gate above, and the boundary is this line**: a Gate decides one action inside the city, a gate decides whether a change may merge. Neither counts the other, and neither is written down as a number here — `xtask` counts its own. |
