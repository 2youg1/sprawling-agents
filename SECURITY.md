# Security policy

## Reporting a vulnerability

Report a vulnerability through GitHub's private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability**. That is the only channel. It keeps the report private between you and the maintainers until a fix is published, and it keeps the discussion, the fix and the advisory in one place.

Do not open a public issue, pull request or discussion for a vulnerability, because a public report reaches attackers before a fix reaches people.

A useful report names the version (`sprawling --version`), the platform, the steps that reproduce the problem, and what an attacker gains. Describe a credential or a token by its shape rather than pasting its value.

## Supported versions

Every release is a pre-release. A fix lands in the next release, and older releases do not receive back-ported fixes.
